# 任务来源

团队管理员打开团队页“任务来源”，选择对应项目，粘贴来源工具生成的只读授权地址，并选择开发协调人。保存后，管理员或有项目权限的产品成员可以“拉取需求”。无需下载或上传反馈文件。

授权地址通常为 `https://source.example/v1/annotation-feed/授权ID#token=凭据`。服务器将片段中的凭据作为 Bearer 授权发送；普通看板只显示去除凭据的地址和“已保存读取授权”。必须提供读取授权，不支持匿名拉取。更换来源必须提供新授权，不会转发旧地址的凭据；同一地址粘贴新授权可更新凭据。凭据失效时拉取会失败，不会退回匿名读取。

当前仅允许公网 HTTPS、443 端口，不支持重定向、本机地址或内网地址。来源是本机服务时，不能直接把 localhost 配置给云端。不要将令牌写入 URL 查询参数；授权片段不会被发送为 HTTP 请求路径。

每次主动拉取的新记录存为需求草稿，分析状态为等待授权，由当前拉取用户负责需求确认。按项目、来源地址、外部记录 ID 去重；重复拉取不覆盖已经修改的需求，也不因来源记录更新而重复创建。原始记录链接保留。每个项目配置一个来源，可停用后重新启用。停用或撤销读取不会删除先前已经拉取的数据。

## 来源响应契约

GET 返回 JSON：

```json
{
  "items": [
    {"id":"稳定标识","title":"标题","content":"完整说明与标注上下文","url":"https://source.example/record/123"}
  ],
  "nextCursor": null
}
```

标题最多 120 字符，正文最多 30000 字符，ID 最多 200 字符；每条需有 HTTP/HTTPS 原始记录链接。分页使用 `cursor` 查询参数及 `nextCursor` 响应字段，不跟随来源返回的任意 URL。单次最多 500 条、10 页、4 MiB；超过限制全部不写入，应缩小来源范围。原始截图文件不自动复制，图像仍在来源记录中查看。

拉取远端时不占团队锁，返回后重新校验用户会话、角色、项目权限和配置版本；批次与去重台账在一个事务提交，失败不留下半批需求。重复同一请求可恢复原结果。

## 存储、升级与恢复

授权凭据保存在服务端团队数据库，写入前将团队数据目录设为 0700、数据库设为 0600，目录权限同时保护 WAL 辅助文件；未额外提供静态加密。勿将团队数据库、备份或运行内存交给非授权用户。默认接口、响应与错误不回显凭据。

新增 `team_task_sources` 与 `team_source_imports` 是团队数据库的增量表。保留已有需求、执行数据与来源台账。回退应用前停用来源、备份数据库；旧版忽略新增表，勿清空台账，否则重新接入可能重复创建需求。源服务的读取授权可独立撤销。
