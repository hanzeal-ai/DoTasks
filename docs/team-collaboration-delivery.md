## 已实现的闭环

A 上传需求及附件 → 本地 Codex 只读分析 → 回答问题并确认模块边界 → 提交需求 → 云端筛选合格成员并取得 Laya 建议 → A/协调人确认分配 → B 本地只读分析、提问或申请重新分配 → B 确认当前版本 → 隔离工作区开发及独立会话审查 → B 确认交付 → 协调人实际集成验证 → A 验收。

- 团队成员资格和项目授权由服务端逐次检查，附件同样受项目权限约束；个人任务库与团队任务库隔离。
- 团队需求、模块继续引用 core requirements/tasks；开发、审查及交付复用 task_runs。团队确认和版本绑定不复制核心执行状态。
- Laya 只为合格候选排序，不写归属或运行状态。无效、过期或不可用的输出退回人工分配。候选版本、容量和任务版本在分配时重新检查。
- 原子事务和幂等回执保护任务变更；离线分析队列持久化。租约过期或未知会话不静默重试：成员先确认本地会话已停止，再启动新尝试。
- 范围变化使受影响模块及其依赖的旧确认失效，拒绝旧运行回调。活动任务先停机确认，重新分配时清理旧执行契约并保留历史。
- 开发与代码审查禁止绑定同一会话。交付绑定实际版本、验证结果及审查门禁。集成验证在协调人本地执行命令，要求干净工作区、指定 HEAD 和所有模块交付提交均被包含。

主要实现：`core/team_schema.py`、`taskboard/cloud/team_*.py`、`taskboard/team_local.py`、`taskboard/team_agent.py`、`web/src/TeamApp.jsx`。现有账号、CLI、发布相关并行修改属于共享工作区基线，没有覆盖或回退。

## 使用前提与步骤

1. 使用支持团队路由的多账号云端版本，成员先注册账号。远程团队 API 要求 HTTPS；本机回环可用 HTTP。每位参与执行的成员保持自己的本地 Agent 在线且 Codex 已登录。
2. 打开 `/team`，创建团队、添加成员和项目。项目登记一致的 Git origin 和完整基线提交；分别授予成员项目权限、模块能力和容量。
3. 每位参与分析、开发或集成的成员，在自己的电脑执行页面给出的命令：`dotasks team-bind --team <团队ID> --project <项目ID> --path <本地仓库>`。本地仓库必须具有登记的 origin 和基线；成员之间无需相同绝对路径。
4. 自动只读分析默认关闭。成员可以逐次启动，或明确启用自己的自动分析并设置预算。实际模型验证使用 20000 token 预算；较小预算可能在完成前被中断。
5. 按页面完成上述角色流程。B 的开发在独立 Git worktree 中执行；不会因模型建议自动推送或合并。协调人先在自己的绑定仓库取得并集成各模块交付提交，再填写集成 HEAD、测试命令和证据，服务端要求本地实际验证成功后才能由 A 验收。
6. 如需 Laya 建议，在云端配置 `DOTASKS_DECISION_MODE=rank`、`DOTASKS_DECISION_URL` 和令牌文件，运行含 `/v1/assignment/recommend` 的 v3 服务。默认 off 时仍可人工分配。部署方式见 `services/laya-dotasks-decision/README.md`。本次没有重启旧的本地常驻服务来冒充新版已部署。

## 数据、恢复与发布边界

附件每次最多 4 个，图片每个 2 MiB、文本每个 256 KiB，合计 4 MiB，支持 PNG、JPEG、UTF-8 文本/Markdown；内容存于团队数据库。分析回执保存在成员本地私有目录，团队数据及备份受持有者控制。本次未添加自动保留期或删除功能，删除真实数据需要另行授权。

需求、必要代码上下文和附件会发送至成员配置的 Codex 模型账户；Laya 收到分配查询及候选的模块能力、在途数量和容量。第三方训练使用取决于实际账户及提供商设置，本实现不改变该设置，也不承诺统一的数据留存政策。

恢复方案：先暂停派发并停止本地执行、确认会话已停止；一致备份账号库、团队库、个人库及配置；使用匹配代码版本和备份恢复，核对团队/项目授权、需求版本、模块归属、运行绑定和交付证据后再恢复派发。不要用旧版本程序直接打开新团队数据并假定兼容。生产备份恢复演练及目标环境检查尚未执行，必须在真实发布前完成。

团队表为本次新增的未发布 Schema；已测试新团队库及现有个人核心路径，不支持把早期实验团队库当作已有生产迁移版本。现有实验数据若需保留，应先明确其 Schema 并设计迁移。

## 后续审查修复（2026-09-24）

本轮只修改与本地验证，未提交或部署。修复四项审查发现：

- 将只读分析放入独立工作线程，同一 Agent 同时最多一个分析；主循环继续同步云端停止状态，不再等待最长 20 分钟的分析完成。
- 请求停止时清除集成证据；集成和最终验收同时要求模块无待处理状态、当前 revision 已确认且已交付。
- 模块依赖校验使用访问中/已完成标记，避免密集 DAG 的指数级重复遍历，保留缺失依赖和循环拒绝。
- 项目撤权只被未完成的产品/协调职责阻止；已验收历史需求不再阻止撤权，活动运行保护保持有效。

新增 `tests/test_team_review_regressions.py`，覆盖分析期间停止与不重复领取、停止后的集成/验收拒绝、30 模块密集依赖、循环和缺失依赖，以及已完成/未完成需求的撤权差异。恢复方式为停用新版本并恢复匹配代码；本次未改变 Schema 或迁移数据。
